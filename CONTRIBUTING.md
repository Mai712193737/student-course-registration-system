# Contributing

Thank you for contributing to the Student Course Registration System.

## Workflow

1. Create a focused branch from `main`.
2. Make one logical change per branch.
3. Keep HTML, CSS, and JavaScript separated.
4. Test the affected page at desktop and mobile widths.
5. Check the browser console for errors.
6. Update documentation when behavior or project structure changes.
7. Open a pull request with a clear summary and test notes.

## Branch Naming

Use descriptive names:

- `feature/course-catalog`
- `feature/student-registration`
- `fix/schedule-overlap-validation`
- `docs/update-use-case-mapping`

## Commit Messages

Use short, imperative messages with a type prefix:

- `feat: add course catalog page`
- `fix: prevent duplicate active registrations`
- `docs: document waiting list rules`
- `style: improve dashboard responsiveness`
- `refactor: separate registration storage logic`

## Pull Request Checklist

- [ ] The change matches an existing requirement or is clearly marked as an enhancement.
- [ ] No unrelated files were changed.
- [ ] The page works at mobile and desktop sizes.
- [ ] No new browser-console errors are introduced.
- [ ] Documentation is updated when needed.
